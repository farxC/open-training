O que precisa acontecer no código — em qualquer cenário

O dark mode não é um toggle: hoje existem 730 cores hexadecimais escritas à mão em 81 arquivos. Toda direção acima depende primeiro de uma camada de tokens. Essa é a mesma fundação para os quatro cenários — só o mapa de valores muda.

ETAPA 01

Camada de tokens semânticos

Tema em src/theme/: light e dark com as mesmas chaves (bg, card, border, ink, accent…). Nenhum hex fora daí.

ETAPA 02

Tailwind com dark:

NativeWind 4 já suporta darkMode:"class". As classes bg-surface viram pares bg-surface dark:bg-surface resolvidos por variável CSS — sem duplicar markup.

ETAPA 03

Migrar os 730 hex

Codemod por lote: os 10 valores mais frequentes cobrem ~78% das ocorrências. O resto entra a mão, arquivo a arquivo, priorizando SessionCard, profile e SetLogger.

ETAPA 04

Charts & Skia

Victory Native e Skia recebem cor por prop, não por classe. Precisam ler o tema via useTheme() — ponto de atenção em VolumeChart e ResistanceCurveChart.

ETAPA 05

Preferência persistida

Três estados: claro / escuro / sistema. Guardar em user_meta (já existe), ler antes do primeiro render para evitar flash branco na web.

ETAPA 06

Chrome nativo

StatusBar, tabBarStyle, fundo dos modais e ::selection na web precisam seguir o tema — são os pontos que denunciam um dark mode incompleto.

Recomendação: começar pelo Caderno escuro. Ele reaproveita a identidade atual (Fraunces + Hanken + JetBrains Mono), então a Etapa 01–03 já entrega valor visível sem rediscutir layout. Direções 2–4 podem entrar depois como refinamento por tela, sobre a mesma fundação de tokens.

Atalhos: 1–4 alternam cenários · D alterna claro/escuro
